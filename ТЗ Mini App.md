# Telegram Mini App «Запись на встречу»

Дата: 28 октября 2026 года.
Статус: проект ТЗ для согласования. Прикладной код Mini App ещё не написан.

## 1. Основание и согласованные решения

Основание: транскрибация урока 6-7, домашнее задание со скриншота, существующие требования и код Telegram-бота @FinDir41bot.

Пользователь разрешил подготовить ТЗ, разработать и проверить Mini App, разместить на Beget через GitHub и настроить запуск из Telegram. До разработки показываем ТЗ для согласования согласно выбранной последовательности работы.

Уже согласовано пользователем:

- Название: «Запись на встречу».
- Главная фраза: «Выберите удобное время для встречи с Дмитрием».
- Светлый фон, тёмный текст, зелёные акценты; поддержка тёмной темы Telegram.
- Основа — существующий бот записи, а не другой учебный проект.
- Google-аккаунт сейчас не подключаем.
- Сервер — существующий Beget; бот уже размещён в `/opt/googlebot`.

Остальные решения ниже — предложения для первой версии, которые входят в согласование этого документа. Примеры преподавателя не считаются пожеланиями владельца автоматически.

## 2. Цель и границы первой версии

Mini App — удобный интерфейс к тому же боту, его заявкам, профилям и настройкам. Чатовый сценарий продолжает работать. Новая заявка из приложения видна в боте; изменение статуса из бота видно в приложении после повторной загрузки данных.

В первую версию входят:

- главная страница;
- пошаговая запись;
- свои заявки с карточками, отменой и переносом;
- контактный профиль;
- административные заявки, расписание, закрытые интервалы и чёрный список;
- честное отображение состояния Google;
- уведомления через существующего бота;
- локальный деморежим для проверки полного сценария без Google;
- GitHub, публикация на Beget, HTTPS и кнопка запуска из Telegram.

В первую версию не добавляем оплату, несколько владельцев, дополнительные календари, CRM, аналитику, редактируемые шаблоны сообщений, расписание с разными часами для каждого дня недели и автоматическое создание Google-аккаунтов. Это возможное развитие, а не обязательства из урока.

Логотип и портрет не требуются. Личные сведения, опыт, достижения и рекламные обещания не придумываем.

## 3. Роли и идентификация

| Роль | Возможности |
| --- | --- |
| Посетитель Telegram | Запись, свои заявки, свои контактные данные |
| Администратор | Всё перечисленное плюс заявки всех пользователей, решения, настройки и блокировки |
| Посетитель обычного браузера | Страница с предложением открыть бота; без доступа к данным и операциям |
| Локальный тестовый пользователь/администратор | Только демоданные на локальном компьютере |

Роль администратора берём из существующей рабочей базы. Новое назначение администратора не требуется.

Идентификатор пользователя получаем из проверенных сервером Telegram initData. Подстановка `user_id`, `admin=1` или имени пользователя в адресе/теле запроса не даёт прав. Пользователь видит только свои заявки, а административные запросы проверяются на сервере каждый раз.

## 4. Главная страница и навигация

Компактный заголовок «Запись на встречу», согласованная фраза, краткая подпись часового пояса и две основные кнопки:

1. «Новая заявка».
2. «Мои заявки».

«Мои данные» — дополнительное действие. Администратору также доступно «Управление» с количеством заявок на согласовании.

Не выводим служебную роль пользователя, технический адрес сервера, счётчик заблокированных и повторяющиеся заголовки. Не занимаем верх экрана пустым декоративным блоком.

Пользователь может вернуться назад в процессе записи. При выходе из незавершённой формы приложение спрашивает, нужно ли отбросить введённое. Между шагами значения сохраняются; постоянного хранения черновика после закрытия приложения в первой версии нет.

## 5. Сценарий новой заявки

Предлагаемый порядок отличается от нынешнего чатового сценария только удобством ввода; правила записи остаются общими:

1. Тема встречи — обязательная, до 150 символов.
2. Длительность — 15, 30, 45, 60 или 90 минут; 30 минут визуально рекомендованы, переход требует явного выбора/нажатия.
3. Дата — компактный список дней текущей недели с переключением недель в пределах горизонта записи.
4. Время — только проверенные свободные начала с шагом 30 минут.
5. Контакты — имя и фамилия, почта; значения подставляются из профиля, имя при первом открытии — из Telegram. Можно изменить.
6. Описание — необязательно, до 1500 символов; можно совместить с экраном контактов, если это не ухудшает мобильную верстку.
7. Проверка — тема, дата, начало/окончание, длительность, часовой пояс, контакты и описание; кнопка «Отправить на согласование».
8. Результат — номер заявки, статус, срок решения, переход в «Мои заявки».

Тема отражается в компактном заголовке следующих шагов. Имя — от 1 до 100 символов, почта — до 254 символов с проверкой формата. Проверки выполняются и в интерфейсе, и на сервере. Номер телефона не запрашиваем.

При изменении даты/длительности прежнее время сбрасывается. До отправки слот не резервируется. При отправке доступность проверяется повторно. Конфликт возвращает на выбор времени с понятным сообщением; заполненные контакты и тема сохраняются.

Повторное нажатие и сетевой повтор одной отправки не создают вторую заявку. Для этого нужен устойчивый ключ операции, проверяемый сервером, а не только блокировка кнопки.

## 6. «Мои заявки»

Три короткие вкладки:

- «На согласовании» — pending и выполняющееся согласование;
- «Предстоящие» — согласованные будущие встречи, включая выполняющуюся отмену с отдельной отметкой;
- «Архив» — завершённые, отменённые, отклонённые, перенесённые, конфликтные и просроченные.

Карточка показывает номер, тему, дату, время и статус. Подробности открываются поверх списка без лишней вложенности. В разделе один раз явно указывается часовой пояс; в итоговой карточке/уведомлении он также присутствует.

Предстоящие встречи сортируются по ближайшему началу. Ожидающие — по ближайшему сроку решения. Архив — от новых к старым. Предусмотрена загрузка следующих карточек, а не бесконечная выдача всех записей одним запросом.

Отмену подтверждаем отдельным действием. Перенос доступен только для будущей согласованной встречи: старая встреча сохраняется до успешного согласования новой даты. Ссылку Meet показываем понятной кнопкой, если она действительно сохранена.

Пустой список имеет короткую подпись и полезное действие. Ошибка загрузки имеет кнопку повтора. Технические значения статусов пользователю не показываем.

## 7. Профиль

Поля: имя и фамилия, электронная почта. Telegram ID/username пользователь вручную не меняет.

Сохранённый профиль общий с ботом и используется при следующей записи. Смена почты профиля не переписывает уже отправленные заявки и приглашения. Профиль не удаляется при очистке старых заявок.

## 8. Администрирование

### 8.1. Главная управления

Компактное меню:

- «Заявки на согласовании» с количеством;
- «Все заявки»;
- «Расписание»;
- «Закрытые даты и часы»;
- «Чёрный список»;
- «Google Календарь».

Не дублируем настройки и показатели во всех разделах.

### 8.2. Решения по заявкам

Карточка содержит данные заявки, контакты и срок решения. Администратор может согласовать, отклонить с необязательным комментарием до 500 символов или заблокировать пользователя после подтверждения.

При блокировке ожидающие заявки пользователя отклоняются, резервы освобождаются. Уже согласованные встречи автоматически не отменяются. Чёрный список позволяет разблокировать; старые отклонённые заявки не восстанавливаются.

Изменение статуса появляется после ответа сервера. При сетевом сбое интерфейс не сообщает об успехе и позволяет проверить результат до повтора.

### 8.3. Расписание и ограничения

Сохраняем значения существующего бота, а не копируем пример преподавателя:

| Настройка | Текущее значение по умолчанию в коде |
| --- | --- |
| Часовой пояс | Asia/Kamchatka |
| Рабочие дни | Понедельник — пятница |
| Общие рабочие часы | 09:00–18:00 |
| Запись не позднее чем за | 24 часа до встречи |
| Горизонт записи | 30 дней |
| Максимум встреч в день | 4 |
| Перерыв до/после встречи | 0 минут |
| Срок согласования | До 48 часов, но не позже начала встречи |

При запуске читаем фактические сохранённые настройки из базы: они имеют приоритет над умолчаниями.

Часовой пояс выбирается из понятного списка российских зон с городом и смещением относительно Москвы; допускается сохранение уже настроенной корректной IANA-зоны. При отправке используется стабильный идентификатор, например Asia/Kamchatka, а не текст названия.

Для непонятных параметров даём короткую подсказку по нажатию:

- «Запись не позднее чем за» — минимальный запас до начала новой встречи.
- «Перерыв до/после» — свободное время вокруг уже занятых интервалов.

Можно закрыть дату целиком или промежуток внутри даты и удалить исключение. Некорректное время, конец раньше начала, отрицательные/чрезмерные значения не сохраняются. Сохраняем ограничения существующего бота на диапазоны настроек.

Изменения действуют для новой записи, не отменяют встречи автоматически и не переписывают срок уже отправленных заявок.

### 8.4. Google Календарь

Раздел различает «Не подключён», «Доступ проверен» с временем проверки, «Нужна повторная авторизация» и «Не удалось проверить — временная ошибка».

Наличие файлов или истёкший короткий access token сами по себе не определяют работоспособность: при будущем подключении требуется реальный запрос с предусмотренным обновлением токена. Токены и секреты не показываются в интерфейсе.

Сейчас авторизацию не запускаем, Google-данные не запрашиваем и не создаём календарные события.

## 9. Работа без Google и локальная проверка

### Рабочий сервер

Главная страница, профиль, существующие заявки и администрирование доступны по правам. Перед выбором реального времени показываем: «Запись пока недоступна: календарь не подключён».

Не выдаём расписание без проверки календаря за свободное. Отправка, согласование и перенос, которым нужна календарная проверка, заблокированы и на сервере. Можно отменить ожидающую заявку и отклонить её без Google; отмена реального календарного события требует действующего подключения.

Не используем демоданные или фиктивную ссылку Meet в рабочей базе. Не отправляем тестовые уведомления реальным пользователям.

### Локальный деморежим

Отдельная база с вымышленными пользователями, заявками и занятыми интервалами. Можно пройти пользовательский и административный сценарий целиком, включая условное согласование и конфликт времени.

Видимая отметка «Демонстрация — встречи не создаются». Запуск только на 127.0.0.1. Демоадминистратор не является реальным Telegram-администратором, не использует рабочие Google/Telegram-секреты и недоступен в серверной конфигурации.

Демопроверка подтверждает интерфейс и правила, но не реальное создание Google Meet, рассылку приглашений и работу внутри Telegram. Эти проверки фиксируем отдельно как отложенные до Google-авторизации.

## 10. Интерфейс и доступность

- Основной экран рассчитан на телефон; проверяем ширины 320, 375, 390 и 430 px, а также настольный браузер.
- Нет горизонтального прокручивания страницы, обрезанных кнопок, выезжающих вкладок и необоснованного пустого пространства сверху.
- Светлая и тёмная тема Telegram; зелёный акцент сохраняет читаемость в обеих.
- Учитываются безопасные области Telegram/телефона и появление экранной клавиатуры.
- Поля имеют подписи; ошибки находятся рядом с полем, фокус заметен, основные действия доступны с клавиатуры.
- Интерактивные области удобны для пальца, ориентир — не менее 44 px.
- Кнопка отправки показывает загрузку и предотвращает повторное нажатие; успешный результат зависит от ответа сервера.
- Короткие русские тексты, без pending, blacklist, lead time, технических ролей и пояснений устройства программы.
- Во время загрузки — аккуратное состояние ожидания; при ошибке — понятный повтор, а не пустой экран.

## 11. Предлагаемые технологии и устройство

| Часть | Решение | Причина |
| --- | --- | --- |
| Интерфейс | HTML, CSS и JavaScript без сборщика | Небольшое приложение, простое обновление и мало зависимостей |
| Telegram | Официальный Telegram Web Apps JS SDK | Запуск, тема, возврат, безопасные области |
| API | aiohttp в существующем Python-процессе бота | Библиотека уже используется aiogram; не нужен второй набор сервисов |
| Правила | Общие Store и Scheduler из core.py | Одинаковые проверки и состояния в чате и приложении |
| Данные | Существующая SQLite | Сохранение текущих заявок и небольшая нагрузка |
| Запуск | Существующий systemd googlebot.service | Автозапуск, восстановление и один процесс записи |
| Внешний доступ | nginx и действующий HTTPS | API слушает только loopback сервера |
| Код и доставка | GitHub → проверенный выпуск → Beget | Отслеживаемая версия и возврат к предыдущему выпуску |

Ключевое требование: HTTP и Telegram используют один экземпляр Scheduler и общую блокировку для операций, влияющих на доступность/резервы/настройки. Недостаточно открыть ту же SQLite двумя независимыми процессами: их asyncio.Lock не будет общим.

Локальные исходники остаются в текущей папке. Новые части предлагается выделить в `miniapp/` (интерфейс), `web_api.py` (HTTP), `web_auth.py` (проверка Telegram), `demo.py` (локальная демонстрация), `tests/` и `deployment/`. Окончательная структура может уточниться без изменения функциональности.

Существующие файлы и оригиналы транскрибаций сохраняем. Структуру базы расширяем только при необходимости, с резервной копией и проверкой совместимости.

## 12. Требования к API и защите данных

- Сервер проверяет подпись Telegram initData официальным способом HMAC-SHA256 и время auth_date; предлагаемый срок свежести — 1 час, допуск будущего времени — 30 секунд. При истечении просим переоткрыть приложение.
- Не доверяем initDataUnsafe и присланной клиентом роли.
- Секрет бота хранится только на сервере, не включается в JS, HTML, GitHub и логи.
- Доступ к чужой заявке возвращает отказ, даже если пользователь угадал номер.
- Административные действия проверяются независимо от видимости кнопок.
- Запросы изменения используют POST/PATCH/DELETE, а не GET; HTTPS, ограничение размера тела и валидация типов/значений обязательны.
- Только один origin приложения; широкое разрешение CORS и авторизация произвольного сайта не требуются.
- Токен, initData, полные контакты и содержимое заявок не пишутся в технические логи.
- API выдаёт понятные категории ошибок: авторизация, права, проверка полей, конфликт, календарь недоступен, временная ошибка.
- Предусмотрены ограничение частоты запросов и защита повторной отправки заявки; недоступность Telegram/Google не должна приводить к бесконечному ожиданию интерфейса.

Группы API: начальные данные/профиль, доступные интервалы, собственные заявки и операции, административные заявки/настройки/исключения/блокировки, состояние календаря. Итоговые маршруты фиксируются при разработке, без расширения прав.

## 13. GitHub, сервер и запуск из Telegram

Предлагаемый адрес: `https://lugovoy.shop/meet/`. Это предложение; наличие нужных маршрутов и текущую конфигурацию nginx проверяем перед публикацией.

Используем действующий домен и сертификат; новый DNS и новый сервер не нужны. nginx получает отдельный маршрут приложения и API. Перед изменением сохраняем конфигурацию, проверяем `nginx -t` и только затем выполняем reload. Главная страница, www и существующие поддомены проверяются после размещения.

Исходники храним в отдельном приватном репозитории GitHub, предлагаемое имя `googlebot-miniapp`. Если доступный подходящий репозиторий уже существует — сначала проверяем его назначение. Секреты, рабочие базы, Google-данные, логи и временные файлы в репозиторий не попадают. Публикация в учебной ветке ограничивается ссылкой и подготовленным текстом, без самостоятельной отправки сообщения в сообщество.

До публикации разработка ведётся в dev; main содержит проверенный выпуск. Развёртывание идёт из конкретного коммита GitHub, а не из незафиксированных локальных файлов. В первой версии достаточно управляемого запуска доставки; автодеплой на каждый push и хранение root SSH-ключа в GitHub Actions не требуются домашним заданием.

Перед заменой приложения делаем копию кода и согласованный снимок SQLite. При возврате кода не затираем свежие пользовательские заявки старой базой. Перезапуск не меняет назначенного администратора.

В Telegram:

1. Добавляем в личное меню бота кнопку «Открыть приложение».
2. Настраиваем нижнюю кнопку меню «Записаться» с HTTPS-адресом приложения. Это можно сделать через Bot API setChatMenuButton; по возможности настраиваем самостоятельно и проверяем getChatMenuButton.
3. Для отдельной кнопки запуска в профиле бота требуется настройка Main Mini App через BotFather. Если управление Telegram недоступно, предоставляем точные короткие шаги с готовым адресом и явно отмечаем этот пункт как невыполненный.

Bot API не заменяет настройку Main Mini App в BotFather. Если пункт сделан только через API, в отчёте не пишем, что он выполнен через BotFather.
