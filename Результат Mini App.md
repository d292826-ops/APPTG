## Выполнено

Созданы интерфейс «Запись на встречу», пошаговая запись, карточки заявок, контакты, администрирование, расписание, исключения, блокировки, отображение состояния Google, светлая и тёмная темы. Обычный браузер без Telegram не получает доступ к личным данным.

API работает в одном процессе со старым ботом, с общей базой, правилами и блокировкой операций. Подпись Telegram и срок входа проверяются сервером. Повторная отправка одной формы не создаёт вторую заявку, в том числе после перезапуска.

Демо использует отдельную временную базу и вымышленный календарь, слушает только локальный адрес и не отправляет реальных сообщений. На рабочем сервере демонстрационный вход запрещён.

Исходники загружены в публичный репозиторий APPTG, который создал владелец. Ветки dev/main. Токен, рабочие базы, контакты пользователей, логи и Google-данные в него не включены. Выпуск получен на сервере через git clone и git archive конкретного коммита GitHub.

На сервере обновлён googlebot.service через drop-in, добавлен маршрут /meet/ в существующий nginx. Основные файлы сайта не заменялись. Нижняя кнопка Telegram «Записаться» сохранена и её URL подтверждён методом getChatMenuButton; в меню /start добавлена кнопка «Открыть приложение».

## Проверено

- 34 автоматические проверки на Mac и Linux: правила записи, вход, права, чужие заявки, одновременная запись в один слот, постоянная идемпотентность, блокировки, согласование/отмена, настройки и работа без Google.
- Синтаксис клиентского JavaScript — node --check.
- Опубликованные HTML, CSS, JS и health — HTTP 200.
- API без Telegram — HTTP 401; /meet/demo/admin и /meet/.env — HTTP 404.
- Серверная проверка подписанного входа владельца: администратор сохранён, demo=false, calendar=false.
- API слотов без Google — HTTP 503; непроверенное время не выдаётся.
- SQLite integrity_check — ok; тестовые заявки в рабочую базу не создавались.
- nginx -t — успешно, служба active, повторный polling_started после обновления подтверждён.
- lugovoy.shop, www, currency и checking после обновления — HTTP 200.

## Ещё не проверено / не выполнено

- Визуальная проверка браузером, узкие экраны и реальный проход по кнопкам: в сессии нет доступных браузеров. Наличие CSS и успешные API-тесты не доказывают качество отрисовки.
- Реальное открытие приложения из Telegram с аккаунта владельца. Сам API входа проверен подписанным серверным запросом, а не реальной сессией Telegram-клиента.
- Main Mini App в профиле бота: необходим BotFather, который недоступен для управления в этой сессии. Настроенное нижнее меню — отдельный механизм.
- Google Calendar, Meet и приглашения: по просьбе владельца Google не подключали. На сервере реальная запись закрыта; профиль, свои заявки и администрирование доступны.

## Что проверить владельцу

1. Открыть @FinDir41bot и отправить /start.
2. Нажать «Открыть приложение» под сообщением или «Записаться» внизу чата.
3. Проверить главную, «Мои данные», «Мои заявки» и «Управление».
4. «Новая заявка» должна объяснять, что календарь не подключён.
5. Проверить читаемость и отсутствие обрезанных кнопок на телефоне, в светлой и тёмной теме.

Чтобы появилась отдельная кнопка в профиле: @BotFather → /mybots → FinDir41bot → Bot Settings → Configure Mini App / Main Mini App → указать https://lugovoy.shop/meet/ и включить. Названия пунктов зависят от версии интерфейса. Нижняя кнопка меню уже настроена; её повторно менять не нужно.

## Эксплуатация и возврат

- Код: /opt/googlebot; GitHub-клон: /opt/googlebot-github.
- Служба: googlebot.service; HTTP: 127.0.0.1:8087, снаружи только nginx/HTTPS.
- Версия и место резервной копии: /opt/googlebot/release.json.
- Копия перед обновлением: /root/googlebot-backups/20261028-015459 (код, настройки, .env и согласованный снимок базы). Не публиковать: содержит секреты и рабочие данные.
- Возврат кода не должен заменять текущую базу старым снимком, иначе потеряются новые заявки.
- Локальный старый бот не включать одновременно с серверным. manage.sh управляет старым Mac-запуском, а не сервером.
